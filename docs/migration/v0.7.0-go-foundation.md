# Vintar v0.7.0 Go 基盤

[互換性契約](v0.7.0-compatibility.md)と[実装計画](v0.7.0-implementation-plan.md)を基準とする。この段階では Python 側の配布・開発入口を切り替えない。

- `cmd/vintar` は `internal/cli.Run(ctx, args, stdout, stderr) int` を呼ぶ。CLI が引数・診断・終了値を所有する。未接続コマンドに成功レポートや成果物を返さない。
- `internal/strictjson` の `Parse` と `Canonicalize`、`internal/casefile` の `Parse`、`internal/report` の batch レポート型は、ファイル公開や通信を行わない。呼び出し元の用途別にバージョン・検証ルールを選ぶ。一つの正規化関数をすべてのダイジェストに流用しない。
- `internal/discovery`、`internal/review`、`internal/execution`、`internal/execution/internal/httpio`、`internal/decision` は実装計画で予約する。利用者ができるまで空パッケージや送信インターフェースを追加しない。
- 標準ライブラリを優先する。TOML の構文処理には `go-toml/v2`、JSON Schema 検証のテストには `jsonschema/v6` を固定して使う。スキーマ検証ライブラリは製品の依存に含めない。外部依存の追加・更新はライセンス、Go 1.26.0、CGO 無効、入力境界、対象プラットフォームを確認する。
