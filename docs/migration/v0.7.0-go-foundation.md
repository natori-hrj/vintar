# Vintar v0.7.0 Go 基盤

[互換性契約](v0.7.0-compatibility.md)と[実装計画](v0.7.0-implementation-plan.md)を基準とする。この段階では Python 側の配布・開発入口を切り替えない。

- `cmd/vintar` は `internal/cli.Run(ctx, args, stdout, stderr) int` を呼ぶ。CLI が引数・診断・終了値を所有する。未接続コマンドに成功レポートや成果物を返さない。
- `internal/strictjson` の `Parse` と `Canonicalize`、`internal/casefile` の `Parse`、`internal/report` の batch レポート型は、ファイル公開や通信を行わない。呼び出し元の用途別にバージョン・検証ルールを選ぶ。一つの正規化関数をすべてのダイジェストに流用しない。
- `internal/discovery`、`internal/review`、`internal/execution`、`internal/execution/internal/httpio`、`internal/decision` は実装計画で予約する。利用者ができるまで空パッケージや送信インターフェースを追加しない。
- 標準ライブラリを優先する。TOML の構文処理には `go-toml/v2` v2.3.1 を使い、v0.6.0 と同じ TOML 1.0 に固定する。JSON Schema 検証のテストには `jsonschema/v6` を固定して使い、製品の依存に含めない。ケースのホスト照合では `x/net/idna` の Punycode コーデックと `x/text/unicode/norm` の NFC 検査を使う。一般の IDNA lookup マッピングは使わず、照合に必要な文字・文脈プロパティをロック済み参照版のデータから生成する。外部依存の追加・更新はライセンス、Go 1.26.0、CGO 無効、入力境界、対象プラットフォームを確認する。

## この段階で確認できること

- CLI は `version`、help、引数解析と事前の拒否を扱う。処理が未接続のコマンドと、`--show-completion` / `--install-completion` は未実装を stderr に示し終了 2。ファイル作成や補完登録はしない。これは移行途中の制限であり、互換性契約の変更ではない。
- Case Schema v1/v2 の TOML、strict JSON、canonical bytes と SHA-256、JSON Pointer の選択、RFC 3986 クエリ符号化を通信なしで検証する。ケース内の照合にはスキーム・ASCII ホストキー・ポートを使い、Unicode 表記と同じ有効な A-label は一致させる。幅変換、case folding、パーセントエスケープから Unicode への変換で一致を追加せず、元の URL は書き換えない。登録 DBMS 診断文の検査、信頼済みポリシーの取り込み、送信側の最終的な対象照合は未実装。ケース読取り成功は実行許可を意味しない。
- 旧バッチレポートと現行 golden を公開スキーマで照合し、Go の `report.Batch` で件数・順序・プロセス終了値との整合を確認する。チェック固有の判定やレポート生成は行わない。OpenAPI の解析・成果物生成も未接続。

```sh
GO_ROOT=/path/to/go1.26.0 bash scripts/check_go_foundation.sh
GOTOOLCHAIN=local CGO_ENABLED=1 go test -count=1 -race ./...
```

前者は CGO 無効のテストと全5対象のビルドを行い、対応するネイティブホストの成果物だけを起動して基盤の CLI を照合する。後者は C ツールチェーンのある対応ホストでのみ行う別枠の検査で、配布物には使わない。
