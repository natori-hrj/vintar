### 承認済みの互換性例外

対象は保全候補 `f37621731fe3f16c8d847451fddc84d20202e049` からの是正。契約書そのものは変更しない。

- **C4:** 未作成の前置成分で隠れていたリンクを `..` が露出する場合も、安全のため拒否する（例 `missing/../linked/../drafts`）。参照版が空選択で成功する場合でも、終了2、stderr にリンク／非ディレクトリ診断、stdout と成果物なし。入力・出力の分離、リンク拒否、非上書き、排他的公開は維持する。失敗後に空の親が残ることはブロッカーとしない。対象 OS の競合・中断・実機ファイル操作は R1 で判定する。
- **C5/C7:** 操作定義の SHA-256 を、展開木を作らず正規化バイトの逐次出力から計算する。1回のコマンドで全操作を合算し、参照の出現は **16,384 回**、現在の参照経路は **128 件**、正規化出力は **16 MiB**、決定的な作業量は **33,554,432 単位**まで。キャッシュ済みの参照も数える。作業量は値・走査するキー・キー処理と比較の保守的な見積もり・ポインター構築と参照解決に課金する。乱数化された map の巡回順は採否に影響しない。予算内では共有・循環の表現も含めて参照版のバイト列を維持する。これらは公開入力上限や出力バッファの拡大ではない。
- **影響:** 参照版が受理する場合でも、幅の広い参照分岐、長い定義参照鎖、複数の操作による共有定義の反復、または長いキー・ポインターの処理が上限を超えれば拒否する。両 POST コマンドとも終了2、stderr に `Error: POST JSON operation definitions exceed the resource limit. Split the spec or simplify shared references.`、stdout なし、成果物の新規作成・置換なし。捕捉した中断は終了130、stdout なし。公開確定前の中断はファイルを公開しない。確定済みの完全なファイルは残り得る。C7 の baseline は別経路で、正規化本文の1 MiB上限を維持する。

上限の根拠は `BenchmarkPostJSONDefinition` の合成測定。6.73 MB・8,191参照の分岐、12.66 MB の複数操作、16,383参照の高密度グラフ、長いキーで3,119万作業単位の入力を含む。16 MiB は測定済みの複数操作を収める余裕を持たせ、参照上限は高密度グラフを収めつつその次の分岐を拒否する。128件の参照経路は実測の50リンクを収め、アクティブな参照とスタックを制限する。作業量上限はバイトや参照だけでは抑えられない長い共通プレフィックスとポインター処理を抑える。ワーク単位は実時間の保証ではない。

この是正は R2 の GitHub Actions 上の実行証拠にはならない。R2 と R1 の残件は維持する。

C1–C3（パーサー、補完、HTTP 特殊 URL）、C10–C11・E1–E3（公開検査、実行・報告の配線）、R1（実機）、R3（配布切替）は引き続き未完了。公開 `verify`、`sqli verify` は fail-closed。
