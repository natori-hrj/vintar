# v0.7.0：URL の役割別受け入れ仕様

実装基点は `67440718ae2ee1a3624536421808331f00851046`。承認済みの[互換性契約 v1](v0.7.0-compatibility.md)（`0a1a7a20d111211820c05461dd4894e35ee11163`）は変更しない。参照は v0.6.0（`712e507f04684d0cc9ba1f62bec6448b274ac87c`）。

## 保存ケース：Phase 3 の有限比較

入口は `casefile.Parse`（Case Schema v1、v2 GET、v2 POST）。実行先への付け替え、信頼済み設定による認可、接続と送信は別の処理であり、Phase 3 の照合キーをそこに渡さない。入力文字列は書き換えない。

| 入力 | 受理・比較 | 安全性の判定 |
| --- | --- | --- |
| ゾーンなし IPv6、生の `%eth0`、数値 `%7`、`%25eth0`、単独の `%25` | 同一の有効な綴りを受理。参照版どおり ASCII 大小文字を比較時に揃える。`%7`／`%07`、`%eth0`／`%25eth0`、ゾーンあり／なし、異なるゾーンは不一致。空のゾーン・`%` の重複を拒否。 | ゾーンの復号、数値や実インターフェースへの解決はしない。 |
| 既定・別ポート、`+443`、Unicode 十進数字、桁間 `_`、ポート成分の空白 | 有効な表記は 16 ビット範囲内の比較値にする。`0` と符号付きゼロは v1 では拒否、v2 では既定値。負値、範囲超過、非十進数字、不正区切りを拒否。省略と既定値は一致し、別ポートは不一致。 | 保存ケースの数値化は信頼済み設定の受理範囲を決めない。 |
| ASCII ホストの `%`、空白・句読点、IDN、IPv4 | 参照版の ASCII 引用後の綴りを比較し、既存の `%` を復号しない。IDN と対応する有効な A-label は一致。先頭ゼロ付きの4オクテット IPv4 は拒否。 | `%61` と `a`、`%C4%B0` と `İ`、無効な幅変換による別名は一致させない。 |
| credentials・空の userinfo、空の `?`／`#`、宣言 origin の `/./`、v2 の要求パス | URL の役割・版ごとに参照版と照合。宣言 origin のドット除去を v2 要求パスに適用しない。エスケープ付き要求パスは承認バイト列と比較する。 | credentials 付きケースを拒否。照合で承認パスや本文ダイジェストを書き換えない。 |

実行可能なベクトルは `internal/casefile/testdata/url-compatibility-v0.6.0.json` と先行の `hostname-v0.6.0.json`。期待結果は参照版の公開ケースパーサーから採取した。

## リリースで観測済み：モックのみ

`verify` の v1・v2 GET・v2 POST は、実行先の `%eth0`・`%25eth0`・`%7` を終了 2／モック 0 回で拒否した。v2 はゾーン付き承認 origin も拒否した。一方、ゾーン付き保存プレースホルダーを独立に承認されたゾーンなし宛先へ付け替えた各試行は、終了 0／モック 6 回で、観測ホストは `127.0.0.1` のみだった。

直接 CLI では `%eth0`、`%7`、`%25eth0` の各試行が終了 0、`http send` は 1 回、`sqli verify` は 6 回で、raw host には各表記が残った。`sqli verify` で生の `%` と `%25` が混在すると終了 2／モック 0 回だった。`+444`、`４４３`、`04_43` は両 CLI で終了 0／実効ポート `444`、`443`、`443`。`0` と `65536` は `sqli verify` では終了 2／モック 0 回、`http send` では数値がモックに渡った。後者は実際にその値で接続できることを意味しない。直接 CLI の実接続と OS のゾーン解釈は未確認。

## 将来の受け入れ表（全行未実行）

比較単位は公開入口ごとの終了値・stdout・stderr、送信前に観測した宛先、実送信で観測した接続と受信内容。送信前拒否はモックの transport 呼び出し 0 回と、標準経路の接続試行・受信 0 件を別々に確認する。実送信の確認は外部通信を遮断した環境の、管理下にある無害なローカル受信先でのみ行う。

| 公開入口 | 入力 | 期待する受け入れ・比較 | 安全性の判定 |
| --- | --- | --- | --- |
| `verify` v1（付け替え） | ゾーン付き保存 URL、`--authorized`、独立に設定したゾーンなしの `VINTAR_TARGET_ORIGIN` と `VINTAR_ALLOWED_ORIGIN` | 一致する実行先を受理。保存 URL の origin のみを付け替え、元のファイルと raw path は保持する。承認なし・不一致は終了 2／stdout 空／stderr に診断。 | 保存 origin を実行先にも承認元にも使わない。 |
| `verify` v2 GET／POST（付け替えと承認） | 同じ保存条件、`--authorized`、`VINTAR_TARGET_ORIGIN` と独立した `VINTAR_RUNTIME_POLICY_JSON` または `VINTAR_RUNTIME_POLICY_FILE` | 承認は case ID・identity・メソッド・リテラルパス・origin・環境区分に一致させる。POST は operation／baseline のダイジェストと隔離環境・`no_side_effect` も照合。空または無効な inline から file へはフォールバックしない。 | 承認欠落・不一致ではバッチ全体を終了 2 で拒否し、先行ケースも送信しない。 |
