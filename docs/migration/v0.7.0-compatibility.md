# Vintar v0.7.0 Pure Go 互換性契約

契約案の版は 1。実装基点は `f36fed7ca74ed5e89a67fcce3c86e6b2fcf21779`、振る舞いの参照はリリースタグ `v0.6.0` のコミット `712e507f04684d0cc9ba1f62bec6448b274ac87c`。以下のファイルパスは指定がなければ参照コミットで解決する。公開コマンドの挙動は同タグの実装とテストで照合する。

配布対象は Go バイナリ。Python ランタイム、SDK、バインディング、二重エンジンを採用しない。参照用 Python は、既存の履歴と証拠から移行時に期待結果を採取するために使える。認可内部実装 #93–#95、保存候補 #96–#97 など、v0.6.0 に含まれない機能は後続に送る。

`verify` は完全 PASS で 0、FAIL で 1、不完全または INCONCLUSIVE で 3。FAIL は INCONCLUSIVE と不完全に優先し、期待と一致する INCONCLUSIVE も合格扱いから外れる。0/1/3 では stdout に batch report v1 を 1 件出し、stderr に診断を分離する。入力・設定・実行・出力エラーは 2、中断は 130。2/130 ではレポートが欠落・不完全になりうる。stdout、stderr、終了コード、出力ファイルをそれぞれ観測する。オフラインコマンドは成功時に stdout へ完了情報を出し、指定先に成果物を生成する。入力・出力エラーは stderr と終了 2、中断は終了 130。

**受け入れ**。タグの `tests/test_cli_goldens.py` と `tests/golden/cli/` をシナリオ単位で対応づける。Go のバイナリをサブプロセス起動し、終了値、stdout の空／テキスト／単一 JSON、stderr の診断、生成ファイルを比較する。JSON は型と配列順を保持して比較し、期待結果の正規化は fixture ごとに記録する。明示 help、引数なし、未知オプション、必須不足、範囲境界と直外、重複オプション、ファイル競合、中断を個別に扱う。

## データ契約

- TOML は Case Schema v1 と v2 の既存入力を受理する。v2 の同梱スキーマとルート `schemas/regression-case-v2.schema.json` の一致を検証する。欠落・未知フィールド、型違い、重複、条件付き必須、明示空文字と省略の差をタグのローダーで照合する。
- JSON レポートの公開スキーマは `schemas/` を基準にする。batch v1 は過去の fixture も検証する。inventory と POST review の v1/v2 は既存 reader の受理範囲と現行 writer を分けて固定する。draft、review、materialization、単一チェックの出力は CLI golden と実装を照合する。
- OpenAPI 3.0/3.1 のローカル JSON/YAML を扱う。参照の許容範囲、循環、重複、数値と YAML の暗黙型をタグの parser／fixture で比較する。外部参照を取得しない。
- strict JSON は 1 MiB、ルート深さ 0 から深さ 48、整数 4300 桁（符号を除く）。厳密な UTF-8、単一値、重複キー拒否、整数精度、有限の binary64 浮動小数点を守る。サイズなどの上限は各入力経路の実装も照合する。
- ダイジェストの入力は v0.6.0 の canonical bytes。キー順、空白なし、ASCII エスケープ、整数と浮動小数点の区別、配列順、負のゼロ、指数表記を検証する。`core/strict_json.py` と `core/json_body.py` の直列化は呼び出し元ごとに照合する。具体的な JSON Pointer のエスケープと配列添字の境界も保持する。標準 Go JSON では、下記の参照ベクトルと異なるエスケープと数値表記が観測された。
- オフライン成果物は現在の入力から再計算したレビューと照合して生成する。再実行で同一ファイルを再利用でき、異なる既存ファイルとの競合を報告する。入力と出力の同一ファイル判定、失敗時の残存ファイル、ハードリンク利用条件を観測する。

**受け入れ**。タグのケース TOML と JSON fixture、`test_identity_binding_contracts.py`、`test_post_json_{inventory,review}_validation.py`、過去の batch v1 fixture を使う。追加する小さなベクトルは canonical bytes と SHA-256 の両方、受理・拒否の境界、未知フィールド、既存 artifact の再検証を対象にする。通常の Go 直列化で差が出るものを先に赤にする。


| 入力 | v0.6.0 の strict canonical bytes | Go 標準の Marshal 出力（比較実験） |
| --- | --- | --- |
| `{"é":1.0,"b":"<"}` | `{"b":"<","\u00e9":1.0}` | `{"b":"\u003c","é":1}` |

## 実行安全性

- `verify` は実行前に明示の `--authorized` と信頼済み環境設定を要求する。v1 は `VINTAR_TARGET_ORIGIN` と `VINTAR_ALLOWED_ORIGIN`。v2 は `VINTAR_TARGET_ORIGIN` と operator が管理する `VINTAR_RUNTIME_POLICY_JSON` または `VINTAR_RUNTIME_POLICY_FILE` を使う。v1 と v2 の混在バッチは終了 2 で拒否する。ケース情報のみで通信権限は生じない。
- v2 は承認をケース ID、実行 identity、メソッド、パス、origin、環境区分に束縛する。POST はさらに operation と baseline のダイジェスト、隔離環境、レビュー済み `no_side_effect` を要求する。認証情報は承認済み送信時だけ適用し、ケース、レポート、診断に流出させない。
- 送信経路でリクエスト予算、レート、タイムアウト、Time の期限、レスポンスサイズを強制する。リダイレクト、自動リトライ、POST リプレイは禁止。中断後に新規通信を行わない。判定ラベルは既存の公開契約に従う。
- オフラインコマンドは通信件数 0。承認欠落・不一致のケースは送信件数 0。ファイル警告では秘密値を含めず、入力ファイルと既存の異なる出力を保護する。

**受け入れ**。既存の `test_post_json_policy.py` と公開入口の拒否 golden でゲートを固定する。将来の Go テストでは外部通信を切った環境で、承認失敗時の transport 呼び出し数 0 とシークレットの非出力を検証する。承認済みのローカル無害フィクスチャでのみ許可経路を検証し、転送先への通信数 0、上限到達後の追加通信数 0、キャンセルを観測する。時計は制御可能にし、バイナリを使う少数のテストで配線を確認する。
