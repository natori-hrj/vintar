# Phase 4 実行境界の検証と残件

比較基点は `74e9f9b67eb23e513dcc59ae0780dd87497bec5f`。承認済み[互換性契約](v0.7.0-compatibility.md)と[実装計画](v0.7.0-implementation-plan.md)の変更提案ではなく、工程の切り分けを記録する。

## 前回の停止理由

| 区分 | 残件と根拠 |
| --- | --- |
| タスク範囲 | 前回の承認は公開 HTTP、オフライン Discovery、ポリシーファイルまで。`internal/cli/cli.go` の `verify` は `--authorized` を検査した後も終了 2 で、その動作を維持する。公開 `verify` の成功を示すには、旧版で既存の検査リクエストを自動で送る経路と、その判定・報告が必要になる。今回の検証範囲は固定された無害な通信に限る。 |
| 入口・バインド | `casefile.Parse` は単一 TOML のデータ検証、`LoadRuntimePolicy` は信頼済み設定の読取り、`PrepareAll` は渡された承認メタデータの照合と資格情報の解決を担う。公開用の非再帰ディレクトリ列挙・安全なファイル取得、重複 ID・混在スキーマの拒否、v1 と v2 のバッチ別バインドはつながっていない。旧版の根拠は `regression_cli.py` の `_case_paths`、`_load_cases`、`_bind_cases` と `regression/binding.py` の `bind_runtime_target`。 |
| 事前検証・実行制御 | `PreparedOperation` は method・URL・資格情報を持つが、送信内容・ヘッダー・実行単位の計画を所有しない。`Governor.Run` は1操作を制御する。公開互換には、全件の計画とケース予算の合計を確認してから資格情報を読むこと、最も厳しい要求レートとケース別タイムアウト、Time ケース単位の期限、計画時間に対する資格情報の有効期限、v2 の1バッチ1 identity 制約が残る。旧版の根拠は `regression/batch.py` の `run_regression_batch` と `regression/runner.py` の `batch_execution_schedule`・`_authentication_plan`。固定テスト2件の予算判定と `Governor` のバッチ期限を、その代りにはしない。 |

## 今回の検証と工程の提案

`internal/execution/boundary_test.go` では、固定の GET と承認済み golden の POST ベースラインを解析する。独立に設定した origin とポリシーを全件照合し、資格情報、逐次制御、モックまたはループバック送信までを接続する。2 identity は下位の資格情報分離の検証用。観測値にはケース ID・送信開始・ステータス・本文長・切り詰め・所要時間だけを保持し、判定や公開レポートは生成しない。実行境界テストは `go test ./internal/execution -run '^TestExecutionBoundary'` で実行できる。

**工程の提案:** Phase 4 のこの区切りでは、全件 preflight と固定リクエストの実行・観測の検証を受け入れ対象とする。公開 `verify` は未完了のまま記録する。次の工程を Phase 5 とするなら、まず `internal/decision` の **保存済み観測 → 判定・理由** と、**判定・実行内訳 → batch v1／終了値** の変換を、ネットワークなしで旧版の fixture に照合する。公開入口の完了判定は、上表のバッチ入口・制御の契約と合わせて別の受け入れ項目にする。この提案は公開用途や実送信を追加で承認するものではない。

## 独立した受け入れ残件

- **配布先での実行:** 既存の製品実行証拠は Linux amd64。Linux arm64、macOS amd64／arm64、Windows amd64 では成果物の SHA-256 を照合し、CLI・ファイルの競合、ハードリンク、末尾リンク／Windows 再解析ポイントとポリシーファイル、中断（POSIX の SIGINT、Windows の Ctrl+C）を各ネイティブ環境で検証する。クロスビルドは実行証拠に数えない。
- **特殊 URL:** [役割別 URL マトリクス](v0.7.0-url-role-acceptance.md)のうち、公開 `verify` v1／v2 と `sqli verify` の受理・拒否・実効ポート・送信件数は未検証。信頼済み origin は現在 ASCII の限定範囲（IDN／A-label・特殊ポート・ゾーンは拒否）。直接 `http send` のゾーン拒否も、インターフェース選択や wire `Host` の互換を示す結果ではない。今回の固定ループバック検証は、承認済み raw path・query の一組のみを検証する。
