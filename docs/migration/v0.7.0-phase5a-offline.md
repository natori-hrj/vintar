# Phase 5A: オフライン判定と報告

比較基点は `19ef7626c2c77c0e2b44040ec2d9f15608a1a03a`。Phase 4 では実行基盤とテスト内の配線を受理した。公開 `verify` の統合は未完了。[承認済み契約](v0.7.0-compatibility.md)と[実装計画](v0.7.0-implementation-plan.md)は変更しない。

| 工程 | 入出力と受け入れ条件 |
| --- | --- |
| **5A: Decision / Report** | 保存済みの型付き観測から判定と理由を返し、実行済みの結果から公開 batch v1 と終了値を組み立てる。`internal/decision/types.go` が共有型で、Report から Decision への依存のみを認める。通信、ケース読み込み、資格情報、判定のための生レスポンス処理は範囲外。公開 `verify` に接続しない。 |
| **5B: 公開統合の残件** | 非再帰ケース列挙と安全な読み取り、重複 ID／混在スキーマ拒否、v1／v2 の信頼済みバインド、単一 identity、全件事前予算とケース別期限を解決する。承認済みの観測を共有型に変換する責務、判定・報告と終了値 0/1/3、入力・出力エラー 2、中断 130 を公開入口で別途確認する。[実行境界の検証](v0.7.0-execution-boundary.md)参照。 |
| **6: ネイティブ配布先での受け入れ** | 各対象環境で SHA-256 が一致する配布バイナリを起動し、CLI、ファイル競合、ハードリンク、再解析ポイント、ポリシー読み込み、中断の実行結果を採る。特殊 URL は[役割別マトリクス](v0.7.0-url-role-acceptance.md)に沿って送信前と受信側を分けて確認する。クロスビルドを実行証拠とはしない。 |

5A の入力は、Boolean の保存済み要約・正規化結果・確認結果、Time の保存済み比較述語、Error の登録済み識別子と状態に限定する。応答本文からこれらの観測を作る処理、リクエスト生成、実行許可の付与は含まない。テストは既存の v0.6.0 golden と固定された合成観測を使い、既存の reader と writer の受け入れ範囲は区別する。
